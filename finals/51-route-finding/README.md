흐름:
1. 첫 물음 → 결과 먼저(확정의 물듦 → 고속도로로 도는 길, 되감기) → 목적지를 넣으면 길 하나가 곧바로 그려짐.
2. 다익스트라(1956 → 1959 발표): 단순화한 '두 도시' 그물에서 같은 계산이 번지고 길이 켜짐. 큰 숫자는 해.
3. 블록이 걷히고 교차로는 점, 도로는 선 → 선마다 '분'(길이 ÷ 속도) → 두 길의 시간을 더해 감(시내 9.7분 / 고속도로 8.3분).
4. 다익스트라 한 단계씩(1초에 3.8개): 가장 작은 기록의 교차로 확정 → 이웃의 기록을 고침(숫자가 바뀜, 길을 따라 신호) → 같은 시간의 물결 → 목적지에서 온 길을 거꾸로.
5. A*: 다익스트라의 물듦을 잔상으로, 목적지에서 더 먼 쪽에 표시 → 지금 점에서 목적지까지 직선(한색 점선)으로 어림 → 확정 59 → 49개, 같은 길.
6. 큰 도로망(동네 9개): 다익스트라 256개 → 먼 길에 자주 쓰인 선을 위층으로 들어 올림 → 양 끝 동네만 아래층, 사이는 위층(122개, 같은 길). A* 는 182개(계산한 값).
7. 고속도로 한 구간 0.5 km 를 실제 빠르기로: 차 안 휴대전화의 위치 알림 → 구간 안 차들의 평균 속도 → 선의 무게 → 지난 기록 곡선(설명용) 위에서 18시 예측.
8. 고속도로가 막힘(14 km/h) → 같은 계산이 시내 길을 고름 → 막힘이 풀린 평소의 두 길: 시내 4.5 km · 9.7분(짧다) / 고속도로 8.1 km · 8.3분(빠르다).
9. 정리.

**만든 방식**
- 무대: 가상의 동네 하나(격자 56 + 나들목 7 = 교차로 63개, 100 px = 0.5 km)와 그 둘레의 고속도로. 속도는 설명용 값(동네 길 20, 큰길 40, 나들목 50, 고속도로 90 km/h). 신호 대기·회전은 넣지 않았습니다.
- 같은 시계: 확정 순서·기록·고침 신호·길·계기·소리(`make_sound.mjs`)가 모두 `model.mjs` 의 `plan(timeline)` 이 만든 실행(k 번째 확정 시각 = 시작 + k ÷ 빠르기)에서 나옵니다. 고정 개수 반복문은 없습니다.
- 다익스트라·A* 는 교과서 그대로 구현했습니다. 층 방법은 단순화한 설명 모형입니다: 서로 다른 동네의 쌍 144개의 가장 빠른 길에서 5% 넘게 쓰인 선을 위층으로 올리고, 출발·도착 동네 안에서만 아래층을 살핍니다(실제 축약 계층과는 다름 — 각주). 세 방법이 같은 길을 내는 것을 코드로 확인했습니다.
- 색: 난색 = 계산이 하는 일(확정의 물듦, 고른 길). 한색 = 무게를 정하는 바깥 정보(A* 의 직선 어림, 휴대전화의 속도, 막힘). 확정의 물듦은 빛이 아니라 무광 상태색입니다.
- 시간 배율: 알고리즘 장면은 계산 단계라 키커에 실행의 빠르기("1초에 N개", 실행에서 계산)를 적었고 컴퓨터의 실제 계산 시간은 말하지 않습니다. 교통 장면은 실제 빠르기(1 m = 2 px, 차는 크게 그림).
- 지난 기록 곡선(아침·저녁에 느려지는 하루 곡선)은 설명용 값입니다.
