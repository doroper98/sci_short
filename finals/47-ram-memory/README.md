**HDR 판**: [hdr/ram-memory.hdr.mp4](hdr/ram-memory.hdr.mp4) — HEVC Main 10, BT.2020, PQ, 10.4 MB. 빛나는 것(칸에 담긴 전하, 열린 가로줄·주소 신호, 높은 전압의 세로줄과 감지 증폭기의 구동, 전원 표시등)만 흰색(203 nit)보다 밝습니다. 칸 배열의 전하는 넓게 깔리므로 gain 0.3, 큰 그릇의 전하는 0.4 로 낮췄습니다. 빛 지도가 있는 프레임 4,481/4,981(전하가 거의 모든 장면에 있음), 가장 밝은 화소 luma 코드 678(무채색으로 어림해 약 626 nit, 설계 최대 812 nit 아래). **HDR 화면에서 보지 못했습니다.** 유튜브가 쇼츠를 HDR 로 재생하는지, SDR 기기용 자동 변환본의 모습도 확인하지 못했습니다([docs/HDR.md](../../docs/HDR.md)).

**대본은 Fable 검수를 받았습니다**(상위 제작 세션이 Fable 작업자를 띄움). 초안 25문장·770음절 → 확정 24문장·781음절. 필수 15곳(삭제 1 포함) + 선택 5곳 모두 반영: 전원을 끈 뒤 사라지는 시간을 "길어야 몇 분 안에"로(Halderman 2008), '감지 않고'(감지 感知로 들림) → '테이프와 달리', IBM 은 화면 이름표로만, "램의 대부분은 축전기를 쓰는 디램"으로 램 = 디램이 아님을, 인텔 1103 문장 삭제(데나드 방식처럼 들림), 읽기 문장들을 '찬 칸 → 조금 오름, 빈 칸 → 조금 내림 → 크게 키워 1·0'으로 잇게, '쓰지 않는 줄' → '찾지 않는 줄', SSD 는 "읽고 쓰기가 훨씬 느립니다" 등. 자세한 것은 [기획](../../episodes/ram-memory/brief.md) 'Fable 검수'.

0초 프레임이 썸네일입니다: 흰 물음 두 줄 "1초에 15번 넘게 다시 채워야 하는 / 램은 어떻게 기억할까?"와 그 아래 가장 큰 주황 주제어 "RAM"(물음의 약 3.9배). 그림은 위에서 본 램의 칸 배열 — 칸마다 담긴 전하가 산과 해 그림을 이룹니다.

흐름: 첫 물음 → 전원이 꺼지면 그림이 새어 사라짐(되감기, 리프레시) → 테이프는 감아야 하고 램은 주소로 곧바로(찾는 시간 막대) → 트랜지스터 하나 + 축전기 하나가 맞물린 한 칸(로버트 데나드 · IBM) → DRAM 의 D = Dynamic, 가만두면 줄어듦 → 그릇 같은 축전기: 차면 1, 비면 0, 새어서 문턱 아래로 → 1이 0(그래프), 다시 채우는 톱니(채우지 않은 곡선은 점선 잔상) → 한 칸 확대: 가로줄 신호가 문을 열고, 세로줄 전압이 높으면 차고 낮추면 빠짐, 문을 닫아도 틈으로 샘(계기 셋) → 4×6 배열: 가로줄 하나가 한 줄을 엶, 중간 전압의 세로줄이 아주 조금 오르내림(정직한 눈금), 감지 증폭기가 끝까지 키움, 값이 칸으로 되돌아가 다시 채워짐, 세로 번호로 한 칸을 밖으로(주소 = 가로 2, 세로 3) → 리프레시: 커서가 줄을 차례로 훑고 칸 전압이 톱니, 빨리 새는 칸과 보통 칸의 그래프, 1초에 15.6번 → 전원을 끄면 칸들이 문턱 아래로(뒤집힌 칸 수) → 램과 SSD: 전원을 끄면 램 칸은 비고 절연막 속의 전하는 그대로, 읽고 쓰기 시간 막대 → CPU ↔ 램 ↔ SSD → 처음의 배열, 정리.

- 무대: 램 칩 속 칸 배열 하나(위에서 본 격자) → 한 칸의 확대(세로줄 | 문 | 그릇) → 배열의 4×6 조각(세로줄·감지 증폭기) → 다시 배열. 끝에 램 칸과 플래시 칸을 나란히.
- 색: 난색 하나 = 전하(저장된 1, 높은 전압), 한색 하나 = 제어 신호(가로줄, 주소, 전원). 0 과 빈 칸은 어두운 회청.
- 시간 배율: 첫 장면 '전원을 끈 뒤(한 예)'를 압축(시계 0→60초, "한 예 · 기계마다 다름"), 한 칸·읽기는 "아주 느리게"/"수십 나노초를 몇 초로", 리프레시는 "64밀리초를 2.4초로"(머리글 키커에 선언).
- 단순화: 축전기를 그릇, 트랜지스터를 미닫이 문, 전하를 수위로 그린 도식(실제 칸은 깊은 원통형 축전기, 세로줄은 짝으로 비교). 새는 길은 닫힌 문 틈 하나로만 그렸습니다. 세로줄 전압의 ±변화는 칸보다 약 10배 큰 세로줄 정전용량에서 계산한 크기(반쪽 진폭의 약 9%)를 과장하지 않았습니다. 새는 빠르기·약한 칸의 비율·읽고 쓰기 시간 막대는 설명용 눈금입니다.
- 소리: 모두 합성한 설명용 소리(녹음 아님), 사건 56개, 모든 기본음과 잡음 대역은 700 Hz 아래(사용자 규칙). 전원이 끊김 = 낮은 덜컥, 전하가 샘 = 내려가는 음, 리프레시 한 바퀴 = 낮은 틱, 증폭 = 올라가는 음. 화면과 같은 시각표(`sound.json` ↔ `events.json` 대조 통과).
