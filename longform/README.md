# 묶음 장편 — 쇼츠 여러 편을 이은 일반 영상

## 무엇인가

[채널 분석 3판](../docs/CHANNEL_GROWTH.md) 9-4 **방안 6 '피드 밖의 길'**의 첫 시험입니다. 2026-11-16 사용자: "어 너가 생각하는 모든 것들을 다 적용해봐. 무한한 권한과 지지를 보낸다". 이 말 아래 제작 세션이 적용한 것이며, **네 편의 선택·순서, 제목, 형식(세로 그대로 이어 붙인 약 11분 일반 영상)은 제작 세션의 제안**입니다.

- 까닭(O1): 조회수는 새 편의 첫 하루에서만 나옵니다. 11-09 → 11-16 에 기본 노출을 받았던 옛 9편은 편당 하루 2.3회 늘었고, 유입의 89.2%가 쇼츠 피드입니다. 검색·추천(일반 영상의 '다음 동영상', 검색 결과)은 피드와 달리 오래 남는다고 보고, 채널에 피드 밖 표면에 설 영상을 하나 둡니다. 우리 자료가 없으므로 한 편으로만 봅니다.
- `01-detection` — **보이지 않는 것을 찾는 법**: 32 레이더 → 33 SAR → 27 예인 소나 → 38 잠수함 탐지(654.0초, 10:54). 탐지 편들은 기본 노출을 받은 편이 많은 주제(O5 '주제')이고, 앞 편의 원리(메아리로 거리 재기, 구경과 빔 폭, 물속 소리)를 다음 편이 이어 씁니다. 33 SAR 은 노출을 못 받은 편(141회)이라 이 묶음이 두 번째 길이 됩니다.
- 영상(mp4)은 저장소에 넣지 않습니다(원본 네 편 합계 약 88 MB, `.gitignore` `longform/**/*.mp4`). 저장소에는 만드는 법(`recipe.json`)과 올릴 글(`upload.md`)·썸네일·챕터만 두고, 워크플로가 그때마다 만듭니다.

| 파일 | 내용 |
|---|---|
| `build.py` | `recipe.json` 대로 각 편 폴더 바로 아래의 mp4 를 순서대로 이어(concat 필터로 다시 인코딩: libx264 crf 18 · medium · yuv420p · 30 fps, AAC 48 kHz 192 kbps, +faststart) `<slug>.mp4` 와 `chapters.json` 을 만든다. `--check` 는 만든 파일을 검사한다 |
| `thumbnail.py` | 네 편의 0초 프레임(poster.jpg)을 세로 띠 넷으로 놓고 가운데 띠에 큰 제목(GmarketSans)과 작은 줄(Noto Sans KR)을 얹은 1280×720 썸네일 |
| `<NN>-<slug>/recipe.json` | 편 목록·챕터 제목·썸네일 글 |
| `<NN>-<slug>/chapters.json` | `build.py` 가 원본들의 실제 영상 길이(ffprobe)로 쓴 챕터 시각. 손으로 고치지 않는다 |
| `<NN>-<slug>/upload.md` | 제목·설명·태그(finals 와 같은 형식 — `publish/youtube.py` 가 그대로 읽는다) |
| `<NN>-<slug>/meta.json` | `video`·`thumbnail`, `instagram: false`·`tiktok: false` |
| `<NN>-<slug>/thumbnail.jpg` | 썸네일(1280×720, 약 70 KB) |

이음매마다 소리는 그 편의 영상 길이에 맞춰 무음을 덧대거나 잘라(편마다 0.01초 안팎) 소리와 그림이 함께 넘어갑니다. 챕터 시각은 초 아래를 버립니다(챕터를 누르면 그 편 첫 프레임보다 1초 안쪽 앞에서 시작).

## 만들고 검사하기(로컬)

```bash
python longform/build.py longform/01-detection            # 이어 붙이기(4코어에서 약 4분 반, 108.6 MB) + chapters.json
python longform/build.py longform/01-detection --check    # 길이 ≈ 네 편의 합(±0.5초), 영상·소리 길이 차 0.1초 안,
                                                          # 1080×1920 · 30 fps, upload.md 챕터 줄 = chapters.json
python -m publish.youtube longform/01-detection --not-shorts --dry-run   # 업로더 검증(비밀값 불필요, 올리지 않음)
python -m unittest tests.test_longform -v                 # ffmpeg 없이 도는 시험

python pipeline/render/fetch_fonts.py                     # 썸네일을 다시 만들 때만(글꼴은 저장소에 넣지 않음)
python longform/thumbnail.py longform/01-detection
```

챕터 제목을 바꾸려면 `recipe.json` `titles` 와 `upload.md` 설명의 챕터 줄을 함께 고칩니다. 한쪽만 고치면 `--check` 와 시험이 실패합니다. 원본 편을 다시 렌더해 길이가 바뀌면 `build.py` 가 `chapters.json` 을 새로 쓰고, 시각이 달라졌으면 `upload.md` 도 맞춰 고칩니다.

## 올리기(사용자)

1. GitHub → **Actions → youtube-longform → Run workflow**.
2. `dir` 는 그대로(`longform/01-detection`), **`dry_run` 의 체크를 끕니다.** 켠 채로 돌리면 만들고 검사만 합니다(먼저 한 번 켠 채로 돌려 보는 것도 좋습니다).
3. 워크플로가 만들기 → 검사 → `python -m publish.youtube longform/01-detection --not-shorts` 순서로 돌고, 올라가면 `longform/01-detection/youtube_upload.json` 을 main 에 커밋합니다. 같은 영상으로 다시 돌리면 기록의 md5 가 같아 다시 올리지 않습니다(같은 설정의 ffmpeg 이면 같은 파일이 나옵니다 — 버전이 달라 파일이 달라지면 업로더가 '영상 파일이 바뀌었다'며 멈춥니다).
4. 영상은 **비공개**로 들어가고 예약 공개 시각도 걸리지 않습니다. YouTube Studio 에서 보고(챕터가 잡혔는지, 썸네일이 들어갔는지) **직접 공개**합니다. '탐지' 재생목록(방안 6)을 만든다면 함께 넣습니다.

이 폴더는 일정 업로드(`youtube-daily`)·병합 push 업로드·다시 올리기·48시간 점검·인스타·틱톡이 보지 않습니다 — 모두 `finals/<NN>-<slug>/` 만 셉니다. 주간 채널 보고서(`publish/analytics.py`)는 채널 업로드 목록을 읽으므로 이 영상이 '편 없음(?)' 줄로 나타납니다.

## 공개 뒤 볼 것

- **유입 경로**: Studio → 이 영상 → 분석 → 도달범위 → 트래픽 소스. 쇼츠 피드가 아닌 **검색·추천 동영상·탐색·채널 페이지·재생목록**이 얼마인지. 이것이 이 시험의 질문입니다.
- **2일째 뒤의 조회수**: 쇼츠는 첫 하루 뒤 편당 하루 약 2회입니다(O1). 이 영상이 공개 3~14일에 하루 몇 회를 버는지 봅니다.
- **챕터별 시청 지속**: 어느 편에서 많이 떠나는지(첫 편 '오늘은 ~' 도입 뒤인지, 편이 바뀌는 곳인지).
- **구독 전환**: 지금 쇼츠는 조회수 1천 회에 1.3명(9-5 목표 3명).
- **네 원본 쇼츠의 조회수 변화**: 묶음이 원본 쪽으로 보내는지(관련 동영상).

## 알려진 약점

- 각 편이 따로 만든 쇼츠라 **편마다 "오늘은 ~ 알아볼까요?" 도입**과 포스터 → 머리글 전환, 마지막 문장의 포스터가 그대로 들어 있습니다. 네 번 되풀이됩니다.
- **세로 그림을 16:9 플레이어**에서 보면 양옆이 검게 남습니다(데스크톱·TV). 휴대전화 세로 재생에서는 화면을 채웁니다.
- 자막은 화면에 새겨진 것뿐이고 편마다 자막 위치가 그 편의 장면에 맞춰져 있습니다.
- **청취하지 않았습니다.** 이음매의 소리는 스트림 길이(영상·소리 차 0.1초 안)로만 확인했고, 이음매 앞뒤 정지화면은 열어 보았습니다.
- 썸네일은 이 환경에서 만든 SDR JPEG 이고, 일반 영상의 맞춤 썸네일은 영상 처리 완료 뒤 업로더가 지정합니다(실패하면 Studio 에서 직접).
