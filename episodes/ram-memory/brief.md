## 질문

1초에 15번 넘게 다시 채워야 하는 램은, 어떻게 기억할까요?
(답: 램(디램)의 한 칸은 전하를 담는 아주 작은 축전기이고 그 전하는 새어 나간다. 램은 줄마다 읽어서 다시 써 넣는 일(리프레시)을 64밀리초마다 되풀이해, 새어 나간 전하를 사라지기 전에 다시 채운다. 그래서 전원이 꺼지면 잊는다.)

## 첫 프레임 (= 썸네일)

- 주제어: **RAM**(램). 교과서·검색에서 쓰는 이름. 화면에는 로마자 "RAM", 물음과 첫 문장에는 "램"(같은 말).
- 흰 글(물음, 첫 문장과 같은 물음): "1초에 15번 넘게 다시 채워야 하는" / "램은 어떻게 기억할까?"
- 큰 글(주제어): "RAM" — 강조색(난색), 물음 글자 높이의 약 2.5배(물음 약 60 px, 주제어 약 170 px 예정). 시리즈 아님(편수 줄 없음). 답은 쓰지 않는다.
- 0초 그림의 가장 큰 덩어리: 위에서 본 램의 칸 배열(가로줄·세로줄이 엇갈린 격자, 칸마다 작은 그릇) — 칸들에 담긴 전하(난색 빛)가 그림 한 장(산과 해)을 이루고 있다. 아래 끝에 감지 증폭기 띠, 왼쪽에 가로줄 번호 띠.
- 가리고 맞히기: 글만 읽어도 "RAM" / 그림만 봐도 격자 칸에 담긴 비트(메모리 칩 속) → 주제어로 답할 수 있음(그림만으로는 'RAM' 보다 '메모리'로 답할 가능성이 있어, 왼쪽 위 칩 테두리에 작은 이름표 "DRAM" — 0초 프레임에는 넣지 않고 s03 부터).
- 제목 앞부분·첫 문장과 같은 주제어("램").

## 첫 순간 (2026-11-13 · 2026-11-16)

- 첫 물음의 긴장 요소: 숫자 **1초에 15번 넘게**. 본문 s19("64밀리초마다 모든 줄을 한 바퀴씩, 1초에 15번 넘게 다시 채웁니다")과 같은 사실(1000 ÷ 64 = 15.6). 출처 3(64 ms 에 8192번 리프레시, 85 ℃ 이하. 더 뜨거우면 32 ms 라 "넘게").
- 첫 2초 장면 = **전원이 꺼진 뒤의 결과**(이 편이 설명할 현상: 휘발성). 0~1.9초에 칸 배열의 그림이 시간 압축으로 흩어진다 — 칸마다 새는 빠르기가 달라 빛이 군데군데 먼저 꺼지고, 2초 무렵에는 모든 칸이 비어 그림이 사라진다. 인과 사슬의 고리: 전원 끔 → 리프레시 멈춤 → 축전기의 전하가 샌다 → 문턱 아래 → 1이 0이 됨 → 그림이 사라짐. 2.2~3.0초에 "전원을 끄기 전"으로 되감고(칸들이 다시 참), s02 동안 전원 표시가 꺼지며 같은 일을 시계(한 예: 0→60초, '한 예' 표기)와 함께 천천히 보인다.
  - 수치 점검을 넘기 위한 설계: 칸 배열이 화면 위 200~1240 을 거의 채우고, 그림을 이루는 '1' 칸이 배열의 절반 넘게 밝다(어두운 바탕 위의 난색 빛 → 빈 칸의 어두운 회청). 포스터 글 뒤 띠는 반투명. 1초에 10%·2초에 20% 를 못 넘으면 배열을 키우거나 '1' 칸 비율을 올린다.
- 끝 한 줄: s24 동안 결론 글 아래에 "다음 원리도 이어서 — 과학쑛츠"(30 px 이상, 읽지 않음, 길이 그대로).

## 기원·배경

- **이름**: RAM = Random Access Memory. 순서대로 감아 가야 하는 테이프와 달리, 어느 칸이든 주소로 곧바로 닿는다(어느 칸이든 거의 같은 시간). 출처 6.
- **한 칸 = 트랜지스터 하나 + 축전기 하나**: IBM 의 로버트 데나드가 1960년대 후반에 내놓았다(1966년 착상·1967년 출원·1968년 특허 US3387286 — 착상 해는 자료마다 1966/1967 로 달라 대본은 "1960년대 후반"). 출처 1.
- **"다이내믹"**: 전하가 새어 저절로 변하므로 주기적으로 다시 채워야 한다는 뜻. 전원만 있으면 그대로 있는 SRAM(트랜지스터 약 6개)은 '스태틱'. 출처 4.
- **처음 팔린 디램 칩**: 인텔 1103(1970년 10월), 1024비트(1K). 이 칩의 칸은 트랜지스터 셋짜리였다. 출처 2. **대본에서 뺐다**(Fable 검수 — 데나드 방식인 것처럼 들림, 분량). 화면에도 쓰지 않는다.
- **지금**: DDR5 의 표준 칩(다이) 하나는 16기가비트 = 17,179,869,184비트. 출처 5. 대본에서 뺐고, origin 장면에서 칩을 물러나 볼 때 계기 눈금 꼴의 작은 이름표("16기가비트 칩 ≈ 172억 칸")로만 쓸 수 있다(읽지 않음).

## 본질(제1원리)

"램은 새어 나가는 전하를, 사라지기 전에 다시 채워서 기억합니다." (s09 · s24 같은 문장)

- 상위 원리: **축전기와 전하 보존**(전하는 줄로 나뉘어 퍼질 때 양이 보존되고, 퍼진 만큼 전압이 낮아진다 — 전하 나눔) + **새는 그릇은 계속 채워야 한다**(동적 평형에 가까운 유지).

## 메커니즘 단계

1. **쓰기·담기·새기**(cell): 가로줄(워드라인) 신호가 트랜지스터 문을 연다 → 세로줄(비트라인) 전압이 높으면 축전기에 전하가 차고(1), 낮으면 빠진다(0) → 문을 닫으면 갇힌다 → 닫힌 트랜지스터와 주변으로 조금씩 샌다. 화면: 한 칸 확대(그릇 = 축전기, 문 = 트랜지스터), 그릇의 수위가 전압. 계기: 칸 전압–시간 그래프와 '1/0 을 가르는 문턱' 점선.
2. **읽기 = 전하 나눔 + 증폭 + 다시 쓰기**(read): 세로줄을 미리 중간 전압(공급 전압의 약 절반)에 맞춘다 → 가로줄 하나를 열면 그 줄의 모든 칸이 제 세로줄에 이어진다 → 세로줄의 정전용량이 칸보다 약 10배 커서 전압이 아주 조금(±ΔV) 움직인다 → 감지 증폭기가 그 작은 차이를 끝까지(공급 전압 / 0) 밀어 1·0 을 가린다 → 열린 문을 통해 그 값이 칸에 다시 써진다(읽기는 칸의 전하를 흩뜨리므로 반드시 다시 씀) → 세로줄 번호로 필요한 칸만 밖으로 보낸다(가로줄 번호 + 세로줄 번호 = 주소). 출처 7.
3. **리프레시**(refresh): 읽으면 다시 채워지는 성질을 그대로 써서, 쓰지 않는 줄도 차례로 연다 → 모든 줄을 64 ms 안에 한 번(DDR4: 64 ms 동안 8192번 리프레시 명령, 평균 7.8 µs 마다) → 칸 전압은 톱니 모양(새고 → 채우고). 대부분의 칸은 64 ms 보다 훨씬 오래 버티지만 가장 빨리 새는 칸에 맞춘 값. 리프레시가 멈추면 문턱 아래로 → 1 이 0 으로. 출처 3, 8.

- 무대: 램 칩 속 칸 배열 하나(위에서 본 격자 — 전체) → 그 칸 하나의 확대(그릇 + 문, 지시선으로 배열의 그 자리와 연결) → 다시 배열. 왼쪽 가로줄 번호 띠, 아래 감지 증폭기 띠를 끝까지 같은 자리에 둔다. 세계 안의 눈금: 칸 전압 그래프의 세로축(0 ~ 공급 전압, 문턱 = 절반)을 그릇의 높이와 같은 자로 맞춘다(점선으로 이음).
- 채워진 무광 덩어리로 그릴 주인공: 축전기(그릇 — 면과 명암이 있는 원통), 트랜지스터(문 — 판), 칩 다이, 테이프 릴, SSD 칸.
- 빛나는 것과 그 뜻 — `lit()` 안에서 그린다: ① 칸에 담긴 전하(난색, 수위만큼, 새면 흐려짐) ② 가로줄 신호(한색, 열린 줄만 짧게) ③ 세로줄을 흐르는 전하와 감지 증폭기의 구동(난색/어두움) ④ 밖으로 나가는 비트 한 점. 자막·계기·이름표·바탕·그릇의 벽·테이프는 넣지 않는다.
- 난색이 맡는 역할: **전하(저장된 1, 높은 전압)** / 한색이 맡는 역할: **제어 신호(가로줄을 여는 신호, 주소)**. 0 과 빈 칸은 어두운 회청(빛 없음).
- 시간 배율: hook "전원을 끈 뒤 몇십 초를 압축", cell·read "수십 나노초를 몇 초로 — 아주 느리게"(실제 읽기 한 번은 수십 나노초 — 화면 선언만, 대본에 수치 없음), refresh "64밀리초를 약 4초로", 각 장면 머리글 키커에 한 번.
- 글자 셋: 머리글 / 큰 숫자 하나(15번, 64 ms) / 계기 눈금.
- 먼저 렌더할 핵심 장면 약 10초: read 의 전하 나눔 → 증폭 → 다시 쓰기, hook 의 첫 3초.

## 현상·사례

- 전원을 끄면 램의 내용이 사라진다(휘발성). 실험(출처 9): 논문 초록은 "실온에서도 전원이 끊긴 뒤 몇 초 동안 내용을 지닌다"이고, 본문의 측정에서는 기계마다 수 초 동안 거의 그대로였다가 빠르게 흩어진다(새 기계일수록 빠름, 15~30초쯤에 급히 흩어진 예; 오래된 모듈은 몇 분까지 — 2차 요약으로만 확인). 차갑게 하면 10분 넘게 버틴다. 대본 s02 는 Fable 지적대로 "길어야 몇 분 안에 거의 다". 화면의 시계는 한 예로 표시.
- 램과 SSD: SSD(낸드 플래시)는 전하를 절연막에 둘러싸인 곳에 가둬 전원 없이도 지키지만, 쓰는 데 훨씬 오래 걸린다(낸드 한 쪽 쓰기 수십 µs~수 ms, 디램은 그보다 훨씬 빠름 — 수치는 대본에 넣지 않음). 출처 10.

## 단순화 메모

- 관측 사실(출처 있음): 1T1C 칸(데나드, 1968 특허), 인텔 1103(1970, 1024비트), 16Gb 다이, 64 ms 리프레시(8192번, 7.8 µs), 세로줄 정전용량이 칸의 약 10배, 중간 전압 미리 맞춤, 읽기는 칸을 흩뜨리고 다시 씀, 전원을 끈 뒤 몇 초~몇십 초에 흩어짐, SSD 는 비휘발·쓰기가 느림.
- 설명 모형: 축전기를 "그릇", 전하를 "물처럼 차는 수위"로, 트랜지스터를 "문"으로 그림. 실제 디램 칸은 깊은 원통(트렌치·스택) 축전기이고 트랜지스터와 위아래로 붙어 있다. 세로줄은 실제로 짝(BL / BL̄)으로 비교하지만 하나로 그림. 새는 길은 '닫힌 문 틈'으로만 그림(실제로는 접합 누설 등 여러 길).
- 비유: "그릇"(축전기), "문"(트랜지스터). 대본에서 "아주 작은 그릇인 축전기", "트랜지스터가 문처럼"으로 비유임을 드러낸다.
- 시간 압축: hook(몇십 초 → 2초), refresh(64 ms → 약 4초), cell·read(나노초 → 초) — 키커에 선언.
- 숫자 "1초에 15번 넘게": 64 ms 주기에서 1000/64 = 15.6. 85 ℃ 넘으면 32 ms(31번). 칸마다 실제로 가장 늦게 채워지는 간격이 64 ms 라는 뜻(줄마다 7.8 µs 간격으로 차례가 온다).

- 스스로 본 약점: 한 칸·그릇 장면은 그림이 위쪽 절반에 모이고 1000~1240 이 비어 있다. 읽기 장면의 ±ΔV 막대는 정직한 크기라 6 px 쯤이어서 휴대전화에서 잘 안 보일 수 있다("아주 조금" 글로 보탬). '주소' 판이 증폭기 바로 위의 세로줄을 가린다. 자동으로 나눈 자막 큐 몇 곳이 어색하다("아주 작은 그릇 / 같은 축전기", "크게 / 키워", "가둬 전원 / 없이도"). 플래시 칸 그림이 상자처럼 보인다. 0초 프레임의 주황 "RAM"이 주황 칸 위에 놓여 대비를 어두운 띠와 그림자에 기댄다. 첫 장면 시계는 60초에서 멈추는 '한 예'다(대본은 "길어야 몇 분").
