# AI는 어떻게 배우고 답할까 (37)

사용자 주제(2026-11-10, 그대로): "ai는 어떻게 학습하고 추론하는가? 우리가 쓰는 chatgpt나 claude는 어떤 과정을 거쳐 우리가 쓰게 되는가". "이건 스케쥴링 된 영상 업로드 아니고 별도로 내일 아침에 업로드 요청을 할게. 디자인언어와 법칙을 잘 적용해서 만들어." → `config/daily.json`에 넣지 않았다. 병합 push 가 곧 유튜브 비공개 업로드이므로, 병합은 사용자가 업로드를 요청할 때 한다.

## 의도와 범위

- 질문: 대화형 AI는 어떻게 배우고(학습), 어떻게 답하는가(추론)? 우리 손에 오기까지 어떤 단계를 거치는가?
- 핵심 명제: "AI는 다음에 올 말을 맞히는 연습으로 배웁니다." 마지막 문장도 같은 명제.
- 대상 11~16세. 수식 없이, 확률 막대와 손잡이(매개변수의 비유)로.
- 다루지 않음: 트랜스포머·어텐션 내부, 회사별 비공개 세부, 성능 비교. 데이터 센터·GPU·메모리는 이어지는 편의 주제(시리즈 제안)로 남김.

## 기원·배경 (출처)

- 1955년 8월 말 존 매카시·민스키·로체스터·섀넌의 다트머스 여름 연구 제안서가 'artificial intelligence'라는 말을 처음 썼고, 1956년 여름 다트머스 회의가 이 분야의 출발로 꼽힌다. (Wikipedia "Dartmouth workshop"; UMBC 기록은 제안서 날짜를 1955-08-31로 적음)
- 學習의 習: 『설문해자』 "習, 數飛也"(자주 날다), 羽 부. 어린 새가 날기를 거듭 연습하는 데서 '되풀이해 익히다'로 넓어졌다. (zdic.net 習 항목, 『설문해자』 習部) — 대본: "새가 날갯짓을 거듭하는 데서 온 글자로, 되풀이해 익힌다는 뜻".
- 2020 GPT-3: 매개변수 1,750억 개, 학습 토큰 약 3천억 개 (Brown et al., "Language Models are Few-Shot Learners", arXiv:2005.14165). 대본에는 1,750억만 씀.
- 최근 공개 모델의 규모: 메타 Llama 3.1 405B(2024-07) — 15조 개가 넘는 토큰, H100 GPU 1만 6천여 개, GPU 약 3,084만 시간(16,384개로 나누면 약 80일). (Meta AI 블로그 "Introducing Llama 3.1"; The Register 2024-07-23) — 대본: "최근 공개된 한 큰 모델은 15조 개가 넘는 토큰을, GPU 1만 6천 개로 몇 달 동안 배웠습니다."
- ChatGPT: 2022-11-30 공개, InstructGPT 와 같은 방법(사람이 쓴 시범 답으로 지도 미세조정 + 사람이 매긴 순위로 보상 모델 → 강화학습, RLHF). (OpenAI "Introducing ChatGPT")
- Claude: 앤트로픽 "Constitutional AI: Harmlessness from AI Feedback"(arXiv:2212.08073, 2022-12) — 원칙 목록에 비추어 모델이 자기 답을 비판·수정하고, AI 피드백으로 강화학습. 대본: "Claude는 원칙 목록으로 스스로 답을 고치게 하는 방법을 더했습니다."
- 역전파: 오차를 출력에서 입력 쪽으로 거꾸로 전해 각 매개변수의 기울기를 구하는 방법(Rumelhart·Hinton·Williams, Nature 1986). 대본은 연도 없이 이름만.

## 본질과 메커니즘

- 학습: 문장의 마지막 토큰을 가리고 → 모델이 후보마다 확률을 매김 → 정답에 준 확률이 낮을수록 손실이 큼(교차 엔트로피) → 오차를 거꾸로 전해(역전파) 각 매개변수를 손실이 줄어드는 쪽으로 조금 바꿈(경사 하강) → 되풀이.
- 규모: 매개변수 수천억 개, 토큰 수조 개, GPU 수천~수만 개, 몇 달.
- 다듬기: 사전학습만 한 모델은 글을 이어 쓸 뿐 → 사람이 쓴 문답 예시(지도 미세조정) → 두 답 비교 평가(사람 피드백 강화학습) / 원칙 목록으로 스스로 고치기(Constitutional AI).
- 추론: 매개변수는 고정 → 질문 토큰이 층을 차례로 지나 다음 토큰의 확률표 → 하나를 골라 붙이고 → 늘어난 글로 다시(자기회귀). 확률로 고르므로 답이 달라질 수 있음.
- 오해: "인터넷에서 찾아온다?" → 검색 도구를 쓰지 않으면 답은 매개변수 값으로 새로 지은 글. 그래서 그럴듯하지만 틀린 말(환각)이 나올 수 있다.

## 장면 계획 — 영상미 문법

무대 하나, 세로 한 줄: **글 띠**(무광 토큰 타일, y ≈ 600) → **모델**(무광 판, 네 층의 손잡이 = 매개변수, y 732~1028) → **계기**(다음 토큰의 확률 막대, y 1100~1290). 숫자 자리는 오른쪽 위(y 300~520).

- 무광 덩어리: 토큰 타일, 모델 판, 손잡이, 원칙 카드, GPU 칩. 빛 쪽(왼쪽 위)이 밝은 면과 그림자.
- 빛나는 것: 따뜻한 물결(모델의 계산, 순전파), 차가운 물결(정답에서 오는 고침, 역전파), GPU 의 계산 맥박. 손잡이는 물결이 지날 때만 그 색으로 잠깐 밝아진다(사건).
- 난색 = 모델의 계산과 선택(고른 막대, 붙는 타일). 한색 = 정답·사람의 평가·고침(정답 칸, 오차, 문답 예시, 확인). 잔상 = 연회색 점선.
- 시간 배율: 한 번의 순전파·역전파를 약 1초로 느리게(실제는 훨씬 빠름), "몇 달"은 몇 초로 — 키커에 선언. 추론 장면에서는 손잡이가 고정(돌지 않음).
- 글자 셋: 머리글, 큰 숫자 하나(정답 확률, 1955, 1,750억, 15조, 2022), 계기 눈금(막대 이름·백분율). 토큰 타일의 글자는 세계의 물체(글 조각)다.
- 막대의 확률값은 설명용(실제 모델에서 잰 값 아님). 키커 "확률은 설명용".

## 소리

`node episodes/ai-learning/scenes.mjs --emit-sound` 가 장면과 같은 계획(plan)에서 `sound.json`(사건 38개)을 쓴다. 순전파(따뜻한 물결)마다 131 Hz 낮은 음, 역전파(차가운 물결)마다 90→200 Hz 휘익, 타일이 붙을 때 196 Hz, 숫자·표시 틱, 정답·문답 예시 스웰. 모든 기본음 700 Hz 미만, 배경음악 없음.

## 단순화 메모 (화면에는 키커로만 선언)

- 손잡이 = 매개변수의 비유(제목 "손잡이 = 매개변수"). 실제 모델은 층이 수십~백여 개이고 매개변수가 수천억 개. 판의 손잡이 28개, 규모 장면의 판 격자는 상징(키커 "크기는 상징").
- 토큰: 한국어 토큰은 실제로는 글자·형태소보다 잘게 또는 크게 나뉠 수 있다. 화면은 낱말 단위로 단순화.
- 확률 막대의 값은 설명용(키커 "확률은 설명용"). 정답 확률 12 → 22 → 45 → 74%는 학습이 진행되며 오르는 모습의 예시.
- 순전파·역전파를 화면에서 약 1초로 느리게(키커 "한 번을 느리게"), "몇 달"을 몇 초로(키커).
- 다듬기 장면: 지도 미세조정(문답 예시)과 RLHF(두 답 비교)를 각각 한 번의 고침으로 그림. Constitutional AI 는 "원칙 목록으로 스스로 답을 고치게 하는 방법"으로만 설명.
- 오해 장면의 틀린 답 "바다가 비쳐서"는 하늘이 파란 이유에 대한 흔한 오해(실제 원인은 공기 분자의 레일리 산란)를 예로 쓴 것.
