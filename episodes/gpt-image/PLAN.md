# 46번 구현 계획서 — GPT는 그림을 어떻게 그릴까

공통 규칙·부품·파일 구조는 `episodes/gpt-generative/PLAN.md` 1절, 1.1절(다이내믹 지침), 1.2절(화면 구성 규칙), 2~3절입니다(먼저 읽기). 부품은 `../gpt-generative/kit.mjs`, 움직임 도구는 `../gpt-generative/motion.mjs` 를 import 합니다(둘 다 읽기 전용). 이 문서는 46번의 모형·무대·장면입니다.

**상표·저작권이 있는 캐릭터를 닮게 그리지 않습니다.** 예시는 이 편을 위해 직접 만든 몬스터(아기 용, 고양이)입니다.

## 1. 모형 — `episodes/gpt-image/model.mjs`

**그림 몇 장에서 실제로 세어 배우고, 한 칸씩 뽑는 아주 작은 모형**입니다(GPT 가 아님 — README 에 밝힘). 화면의 그림·확률·번호는 모두 이 모형에서 나옵니다. 순수 계산만 하고 `node model.mjs` 로 확인 값을 찍습니다.

- 칸: `G = 20`(20×20 = 400칸). 차례는 왼쪽 → 오른쪽, 위 → 아래.
- 무늬 목록 `PALETTE` 8가지(번호 0~7): 0 바탕(짙은 남색) · 1 윤곽(검정에 가까움) · 2 한색 진함 · 3 한색 중간 · 4 한색 밝음 · 5 난색 진함 · 6 난색 중간(호박) · 7 난색 밝음. 색은 kit `PAL` 의 한색·난색 색조에서 정합니다(다른 색조 금지).
- 공부할 그림 `TRAIN` 9장: (불, 용) 3장 · (물, 용) 3장 · (불, 고양이) 3장. 같은 조합의 세 장은 **숨(불·물)의 모양만** 다릅니다. 빼 둔 조합 `HELD = (물, 고양이)` 는 공부하지 않습니다.
  - 20×20 글자 지도로 직접 그립니다. 생물은 왼쪽(0~11열)에서 오른쪽을 보고, 입은 9~10행·11열 근처. 숨은 12~19열의 부채꼴.
  - 용: 뿔 둘, 등 가시, 몸은 3(한색 중간), 배는 4, 윤곽 1. 고양이: 세모 귀 둘, 수염, 꼬리, 몸은 4(한색 밝음)에 2(진함) 줄무늬, 윤곽 1. 불: 6·7 에 가장자리 5. 물: 4 에 가장자리 3, 방울 몇 개.
  - 굵고 단순한 덩어리로. 처음 보는 사람이 "불을 뿜는 아기 용", "고양이"라고 말할 수 있어야 합니다(미리보기 그림을 열어 보고 그렇게 될 때까지 고침).
- 배우기(세기):
  - 주문의 낱말은 두 자리입니다: 무엇(`용` / `고양이`), 숨(`불` / `물`).
  - 칸마다 **어느 낱말이 그 칸을 정하는지**를 배웁니다: 두 자리 각각에 대해 그 칸의 번호와의 상호 정보량을 `TRAIN` 에서 계산해 더 큰 쪽을 담당 낱말로(`WHO[칸] ∈ {'what', 'breath', null}`, 둘 다 0 이면 null = 늘 같은 칸).
  - 칸의 분포: `P(번호 | 칸, 담당 낱말의 값, 왼쪽 칸의 번호, 위 칸의 번호)` 를 `TRAIN` 에서 세고, 본 적 없는 문맥이면 `P(번호 | 칸, 담당 낱말의 값)` 로 물러납니다. 더하기 평활 α = 0.02.
- 그리기: `generate({what, breath, seed}) → {codes[400], steps[k] = {dist[8], u, pick}}`(걸음마다 `u = rng()`, kit `stripPick` 과 같은 누적 규칙). `{greedy: true}` 도.
- 그림 → 번호: `SMOOTH`(80×80, `TRAIN` 한 장을 4배로 키우고 칸 안에 명암과 경계 번짐을 준 "원래 그림") → 20×20 칸의 평균색 → 가장 가까운 무늬 번호(`quantize`). 원래 지도와 같은 칸의 비율을 확인 출력에.
- 번호 → 그림(화면용 복원): `decode(codes)` — 칸을 4배로 키우고 경계를 부드럽게 한 80×80 색 배열.
- 확산 방식의 설명용 그림: `noisy(codes, level, seed)` — `level`(0~1)의 비율만큼 칸의 번호를 무작위 번호로 바꿈. 차례 `NOISE_STEPS = [1, 0.85, 0.7, 0.55, 0.4, 0.25, 0.12, 0]`.
- **꼭 나와야 하는 결과**(확인해서 보고. 안 나오면 도안·평활을 고치고 무엇을 바꿨는지 보고. 손으로 결과를 적어 넣지 않음):
  1. (불, 용) → 용과 불로 알아볼 수 있는 그림.
  2. '불' → '물' 로만 바꾸면 무엇 담당 칸은 그대로이고 숨 담당 칸만 달라짐(달라진 칸 수).
  3. 씨앗이 다르면 숨의 모양이 달라짐(서로 다른 그림 셋 이상, 그리고 공부한 세 변형과 다른 모양이 하나 이상 나오면 더 좋음).
  4. `HELD`(물, 고양이) → 고양이와 물. 공부한 9장 어느 것과도 같지 않음을 확인.
  5. 낮은 확률의 번호가 뽑혀 눈에 띄는 흠이 생기는 씨앗 하나(`RUN.GLITCH`, 흠의 자리와 그 번호의 확률) — 없으면 평활을 조금 키워 찾음.
  - 씨앗은 찾아서 고정: `RUN.MAIN`(1번), `RUN.WATER`(2번, MAIN 과 같은 씨앗), `RUN.S1~S3`(3번), `RUN.HELD`(4번), `RUN.GLITCH`(5번).
- 미리보기: `node episodes/gpt-image/preview.mjs` → `outputs/gpt-image/review/art.jpg`(공부한 9장, `SMOOTH` 와 그 `quantize` 결과, MAIN, WATER, S1~S3, HELD, GLITCH, `WHO` 지도(무엇 담당 = 한색, 숨 담당 = 난색, null = 회색), `NOISE_STEPS` 여덟 장을 칸 24px 로 이름과 함께).

## 2. 무대

- 주문 글줄(세계): y 300, 조각 56px, `given`(한색): `불을 · 뿜는 · 아기 · 용`. 가로 가운데 정렬.
- 그림판: 20×20칸, 칸 34px → `{x: 200, y: 400, w: 680, h: 680}`. 빈 칸은 가는 격자의 `ghost`. 채워진 칸은 무늬 목록의 색을 가진 **무광 타일**(위 1px 밝은 선, 아래 1px 어두운 선). 그림판의 색은 "세계 안의 그림"이므로 두 색 규칙의 예외가 아니라 그 색조 안의 여덟 색입니다.
- 계기: 무늬 뽑기 띠 — `panel` 안, y 1150, 높이 64. 여덟 칸이 **각자의 무늬 색**으로 칠해지고 너비 = 확률(넓은 칸 안에 번호 0~7). 표지는 kit 과 같은 난색 세모. 무늬 목록(여덟 견본 + 번호)은 token 장면에서 같은 자리에 나란히.
- 기계(GPT): 필요할 때만(읽기 → 확률) 주문 글줄과 그림판 사이 오른쪽에 작게가 아니라, **띠 위의 이름표가 달린 얇은 몸통**으로 둡니다(그림판이 주인공). 읽기는 `sweep`(주문 조각 → 채워진 칸들을 차례로), 한색 펄스.
- 0초 포스터 프레임: 주문 글줄(위), 제목(가운데), 그 아래 작은 그림판 `{x: 360, y: 985, w: 360, h: 360}`(위에서부터 채워지는 중 — 용의 머리까지), 제목이 줄어드는 동안 그림판이 일하는 자리로 커집니다. `POSTER = {q: ['GPT는 그림을', '어떻게 그릴까?'], a: '그림도 한 조각씩', …}`.
- 색: 주문 글 = 한색(주어진 글). 표지·뽑힌 칸의 번쩍·읽기 펄스 = 신호. 빛(Glow)은 **뽑힌 칸의 번쩍과 읽기 펄스**에만. 큰 숫자는 한 번에 하나.
- 시간 배율: 한 칸씩 보이는 구간은 키커 "실제보다 느리게", 빠른 구간은 "빨리 감기" + 배속 표시.

## 3. 장면 (대본 확정 2026-11-13 — 22문장. 낱말 시각은 `wd(tl, sid, 낱말)`, tts 기준)

1단계에서 달라진 것: 공부할 그림은 15장(조합마다 숨 모양 다섯), 평활 α = 0.0005, 물러나기는 (왼쪽, 위) → 왼쪽 → 위 → 칸. 400칸 가운데 확률이 갈리는 칸은 18개뿐이고(모두 숨의 가장자리, 0번과 5번 사이 60/40~80/20), 나머지는 한 무늬가 거의 100% 입니다. **이 사실을 감추지 않고 씁니다**: 첫 칸의 띠는 거의 한 덩어리이고, 확률이 갈리는 칸에서 느려집니다. `RUN.GLITCH` 는 쓰지 않습니다(손가락 문장을 대본에서 뺌).

`model.mjs` 에 더할 것: `TEXT_NEXT`(hook 용 작은 글 조각 표 — `아기 용이 불을` 뒤: `뿜는다` 0.86 · `삼킨다` 0.08 · `본다` 0.04 · 그 밖 0.02, 설명용으로 정한 값이라고 주석), 확률이 갈리는 칸의 목록 `SPLIT_CELLS(run)`.

## 4. 검수에서 볼 것

- 0초 프레임: 제목이 주문 글줄·작은 그림판을 가리지 않는가. 그림판에 이미 용의 머리가 보이는가.
- 그림을 알아볼 수 있는가(용·고양이·불·물). 기존 캐릭터를 닮지 않았는가.
- 띠의 표지가 가리키는 칸의 번호 = 그림판에 놓이는 칸의 색인가. 가속 구간에서 그림판과 띠가 같은 걸음인가.
- 1.2절: 글자 잘림 없음, 머리글 겹침 없음, 창을 채우는 크기, 자막 자리(y ≥ 1376) 비움.
- 빛은 뽑힌 칸의 번쩍과 읽기 펄스뿐인가.
- 확산 장면과 연표에 "설명용 그림"임이 키커로 선언되어 있는가. 가림막이 열리지 않는가.
