# 밀도 있고 입체적인 과학 애니메이션

2026-10-20 사용자 요청: “저런 형태로 영상이 밀도있고 입체감 있게 만들어지도록 저장소를 업데이트 하자.”
이 문서는 앞으로 제작할 영상의 품질 기준이다. 기존 전력 영상이 이 기준을 충족했다는 평가가 아니다.
음향은 [SOUND_DESIGN.md](SOUND_DESIGN.md), 목소리·자막은 [NARRATION_AND_CAPTIONS.md](NARRATION_AND_CAPTIONS.md)를 함께 적용한다.

## 설명의 밀도

한 질문을 관찰 → 원인 작동 → 결과 → 조건 비교로 발전시킨다. 각 변화는 시청자의 이해를 한 단계씩 늘려야 한다.
같은 공간 안에서 이미 본 대상에 정보를 덧붙여 관계를 축적한다. 장면마다 새로운 그림과 문장을 나열해 맥락을 초기화하지 않는다.

- **먼저 현상을 보여준다.** 자막을 읽어야만 변화가 있다는 사실을 알 수 있는 화면은 보완한다.
- **작동하는 부분을 보여준다.** 껍데기 그림에 빛·입자를 얹는 데 그치지 않고, 진동·전파·회전·변환·축적 같은 핵심 과정을 움직인다.
- **주목할 변화를 구분한다.** 핵심 대상과 보조 맥락의 대비·속도·밝기를 조정하고, 비교할 때는 가능한 한 원인 하나를 바꾼다.
- **그래프는 관측 결과다.** 실제로 보여주는 모형의 상태·관측값으로 그래프를 갱신한다. 같은 사건을 다른 방식으로 읽게 할 때만 추가한다.
- **관찰 시간을 확보한다.** 처음 보는 작동은 천천히 보여주고 필요한 부분을 반복한다. 화면을 채우거나 컷을 늘리는 것으로 밀도를 대신하지 않는다.

## 공간과 재질

관측자, 발생원, 이동 경로가 어디에 있는지 읽히는 공간을 먼저 설계한다.
입체감은 원근, 앞뒤 가림, 접촉 그림자, 명암, 상대 크기, 필요한 시차로 만든다.
2D 단면이나 2.5D도 현상의 깊이와 관계를 충분히 설명할 수 있으며 모든 주제에 3D를 강제하지 않는다.

- 대상의 위치·크기·조명 방향·재질을 한 장면 안에서 일관되게 유지한다.
- 확대·단면·분해를 쓸 때 전체에서 어느 부분을 보고 있는지 연결 표시나 연속적인 전환으로 보여준다.
- 카메라는 관측 위치나 구조를 설명할 때 움직인다. 중요 비교에서는 시점을 안정시켜 변수를 읽게 한다.
- 광원·발광·잔상은 실제 광학 현상인지 설명용 강조인지 구분한다. 과도한 빛 번짐으로 파면·구조·자막을 가리지 않는다.
- 생성 이미지는 배경·질감·형태 제작에 사용할 수 있다. 회전·분해·단면이 필요한 부품은 따로 제어할 수 있게 만들고, 핵심 인과는 모형과 시간표로 제어한다.

## 움직임과 소리를 함께 만드는 방식

에피소드에서 필요한 최소한의 상태와 사건을 정한다. 위치·시간·주파수·출력·저장량처럼 설명에 쓰는 값은 한 곳에서 계산하고 영상·그래프·소리가 함께 참조하게 한다.
발생 시간과 관측 도착 시간은 다를 수 있다. 화면의 보기 좋은 타이밍에 소리를 임의로 붙이지 않는다.

가속·감속은 카메라와 안내 라벨에 자연스럽게 사용할 수 있다. 일정 속도의 파동 전파나 물리 운동에 같은 이징을 무조건 적용하면 물리적 의미가 달라지므로 구분한다.
시간 압축, 공간 축척, 과장한 크기, 설명용 음향의 대응 관계는 에피소드 제작 메모에 기록한다.

### 천둥 참고 영상에서 이어갈 설계

첨부 영상의 직접 관찰은 [음향 문서](SOUND_DESIGN.md#첨부-천둥-영상에서-확인한-것)에 있다.
아래는 그 설명 원리를 새 영상에 적용하기 위한 제안이며 원본의 구현 도구·3D 구조를 확인했다는 뜻이 아니다.

| 설명 단계 | 화면 | 소리와 연결 | 시청자가 얻는 이해 |
|---|---|---|---|
| 현상 관찰 | 번개 경로와 관측자를 한 공간에 놓고 파면 도착을 보여줌 | 관측자 도착 시각에 대응하는 소리 | 번쩍임과 들림 사이에 시간이 있음 |
| 원인 분리 | 가까운 구간과 먼 구간을 구별하고 거리 표시 | 같은 전파 속도에서 거리별 도착 차이 | 먼 구간의 소리가 늦게 도착함 |
| 다시 합치기 | 여러 구간의 파면과 도착 시간축을 연결 | 여러 도착음의 겹침과 지속 | 긴 경로가 이어지는 소리를 만들 수 있음 |

거리·시간을 바꿔 비교할 경우 화면과 소리를 함께 다시 계산한다. 실제 천둥의 모든 요인을 이 단순 모형으로 설명하지 않는다.

### 전력 영상에 적용할 개선 방향

기존 `samples/korea-power-day/`는 발전원별 수치 모형과 전체 수급 설명의 출발점이다.
다음 제작에서는 전체 계통에서 선택한 발전원으로 들어가 에너지 변환을 보여주고 다시 전체 흐름으로 돌아오는 구성을 검토한다.

- 원자력·석탄: 열원 → 증기 → 터빈 → 발전기의 연결과 운동. 연료별 열원 차이를 구분한다.
- LNG: 가스터빈의 연소·회전을 보여주고, 복합발전을 선택한 경우 배기가스 열 회수와 증기터빈을 연결한다.
- 수력·양수: 높이 차와 유량, 발전·양수 방향, 저수량 변화를 같은 상태로 표현한다.
- 태양광: 빛에서 전기로 변환되는 과정과 낮의 출력 변화를 구분한다. 모든 발전에 터빈이 있다고 오해하게 하지 않는다.
- 풍력: 바람·회전자·발전기의 관계를 보여준다. 바람과 출력 관계는 채택한 모형 범위 안에서 표현한다.
- ESS: 저장량과 충방전 방향을 함께 바꾼다. 저장을 새로운 에너지원처럼 합산하지 않는다.

설명용 흐름 입자를 실제 전자의 이동 속도나 전력의 도달 시간처럼 소개하지 않는다.
발전량·SOC·그래프·설명용 소리는 같은 데이터를 사용하고, 계통의 60Hz와 발전량 크기를 혼동시키지 않는다.
한 편에서 어디까지 다룰지는 관찰 시간에 맞춰 정하며 모든 내부 구조를 한 화면에 동시에 표시하지 않는다.

## 제작과 결과 확인

1. [에피소드 메모](../templates/episode-brief.md)에 질문, 핵심 인과, 공간 배치, 청각 비교, 단순화 범위를 적는다.
2. 설명이 가장 어려운 구간을 짧게 실제 렌더한다. 가령 8~12초일 수 있으나 고정 길이는 아니다. 제작자가 직접 화면과 소리를 검토하고 문제를 수정한다.
3. 검증한 표현을 전체 길이로 확장하고 실제 음성 길이에 자막·관찰 시간을 맞춘다.
4. 최종 인코딩 결과를 확인하고, 확인한 방법과 남은 한계를 제작 메모에 남긴다.

결과에서는 다음을 확인한다.

- 말과 긴 자막을 빼도 핵심 대상·운동·변화가 보이는가? 언어가 필요한 개념은 별도로 보완했는가?
- 깊이와 카메라가 원인·경로·관측 위치를 읽게 하는가?
- 확대나 전환 뒤에도 같은 대상을 따라갈 수 있는가?
- 그래프·수치·상태·소리가 같은 조건 변화에 반응하는가?
- 중요한 비교를 보고 듣는 동안 자막·음악·장식이 주의를 빼앗지 않는가?
- 휴대전화 크기에서도 라벨과 핵심 구조가 읽히는가? 모노에서도 청각적 차이가 남는가?
- 반복되는 정지 그림, 의미 없는 카메라 이동, 연결 없는 효과음이 설명을 대신하는 구간이 있는가?

자동 디코딩·수치 검사는 기능 검증이고, 연속 재생·청취는 표현 검증이다. 하나로 다른 하나를 대신했다고 기록하지 않는다.
이 기준은 제작 중 판단과 수정에 사용하며 별도의 사용자 승인 절차를 추가하지 않는다.

## 2026-11-07 사용자 피드백: 영상미와 다이내믹함 (이후 모든 편의 기준)

사용자 지적(그대로): "이번에 만든 네가지 영상 굉장히 영상미가 떨어지는데, 다음 영상들은 다이내믹함과 비주얼함을 높여야 해." 대상은 23·24·31·34번이다.
아래 진단과 규칙은 이 지적을 받아 상위 작업이 정리한 적용 방식이다(사용자가 항목별로 확정한 것은 아니다). 20·21번에도 같은 약점이 있었다.

진단 — 무엇이 영상미를 떨어뜨렸나
- 작은 도식 하나를 화면 가운데에 두고, 위아래(특히 자막 위 1000~1450 px 구간)를 비워 두었다. 세로 화면의 절반이 빈 배경이었다.
- 계기판·표·작은 이름표가 많아 '움직이는 슬라이드'처럼 보였다. 글자를 읽어야 이해되는 화면이 많았다.
- 가는 선과 평면 색 위주로 빛·질감·깊이(명암, 빛 번짐, 대기, 입자)가 거의 없었다.
- 카메라가 서 있고 장면 전환이 교차 페이드였다. 화면 안에서 크게 움직이는 것이 적었다.

규칙 — 다음 편부터
1. **꽉 찬 화면**: 장면마다 '주인공 그림' 하나가 무대 넓이의 절반 이상을 차지한다. 배경도 장면의 일부(하늘·대기·플라스마·물·우주)로 화면 끝까지 채운다. 빈 단색 배경 금지. 아래 안전 영역에는 핵심 정보만 두지 않을 뿐, 배경 그림은 이어진다.
2. **빛과 질감**: 빛 번짐(블룸), 가산 합성, 입자, 연기·유체, 그림자·테두리 빛을 기본으로 쓴다. 뜨거운 것은 빛나고, 가까운 것은 크고 선명하고, 먼 것은 흐리고 어둡다.
3. **움직이는 카메라**: 모든 장면에서 카메라가 천천히라도 움직인다(밀고 들어가기, 따라 올라가기, 돌기). 장면 전환은 확대·축소·이어지는 동작으로 잇고, 교차 페이드는 예외로만.
4. **글자는 적게, 크게**: 한 화면의 이름표는 3개 이하, 30 px 이상. 수치는 큰 숫자 하나(80~160 px)로 보여 준다. 여러 줄짜리 계기판·표는 쓰지 않는다. 3단 계기판이 필요하면 큰 그림 위에 작은 겹 표시 하나로 줄인다.
5. **사건의 무게**: 분열·충돌·점화 같은 순간은 섬광, 충격 고리, 짧은 슬로모션, 아주 약한 화면 흔들림으로 강조한다(남용 금지).
6. **2~4초마다 새 움직임**: 한 장면 안에서도 2~4초마다 무언가가 새로 일어난다. 같은 정지 구도가 6초를 넘지 않는다.
7. **과학은 그대로**: 화려함은 모형에서 나온다. 유체·궤적·빛은 실제 물리나 선언한 설명 모형으로 계산하고, 장식용 입자로 인과를 흐리지 않는다.

자체 점검(정지화면을 볼 때)
- 썸네일 크기로 줄여도 무엇인지 보이는가? 화면의 절반 이상이 비어 있는 프레임이 있는가?
- 이름표를 모두 가려도 장면이 읽히는가?
- 연속한 정지화면 두 장(2초 간격)이 거의 같아 보이는가? 그렇다면 움직임이 부족하다.
