# 발음 규정집과 재발 방지 목록

2026-11-28 사용자(73 OpenAI 양자중력이론 완성본을 듣고): "야 잠깐. 상대성이론 발음이 왜저래. '상대썽이론'이어야 되자나"
→ "응 재발 방지 목록과 발음 규정집 같은게 있으면 거기에 다 등록해".
그 전에는 이런 목록이 없었습니다. 이 문서와 `config/pronunciation.json` 이 그 목록입니다.

- **기계가 읽는 규정집**: [`config/pronunciation.json`](../config/pronunciation.json) — 합성 직전에 자동으로 적용됩니다.
- **사람이 읽는 규정**: 이 문서의 '발음 규정'.
- **재발 방지 목록**: 이 문서의 맨 아래 표. 음성·자막에서 사용자가 지적한 일과 그것을 다시 막는 장치를 적습니다.

## 왜 생기는가

표준 음성 엔진(Supertonic 3)은 **글자를 보고 읽습니다.** 받침 뒤의 된소리(물리학자 → [물리학짜])처럼 표기에서 드러나는 소리 바뀜은 잘 읽지만,
**표기에 드러나지 않는 된소리**는 글자대로 읽는 일이 있습니다. '상대성'은 [상대썽]이 표준 발음인데 [상대성]으로 읽었습니다.
제작 세션은 소리를 듣지 못하므로, 듣고 나서 고치는 것이 아니라 **대본 단계에서 미리 적어야** 합니다.

## 발음 규정

1. **표시(`text`)는 맞춤법대로, 발음(`tts`)은 소리 나는 대로.** 화면 자막은 `text` 로 그리므로 `tts` 에 된소리를 적어도 자막은 바뀌지 않습니다.
2. **규정집의 낱말은 저절로 바뀝니다.** `narrate.py` 가 합성 직전에 발음 텍스트(직접 쓴 `tts` 와 자동 변환 결과 모두)에서 규정집의 `write` 를 `say` 로 바꾸고, 바꾼 것을 화면에 알립니다(`발음 규정집 s03: 상대성→상대썽`). 글자 수는 그대로입니다.
3. **규정집에 없는 낱말은 대본을 쓸 때 찾아 `tts` 에 직접 적습니다.** 아래 '찾아야 할 부류'를 문장마다 훑습니다. 대본 검수(Fable)의 항목이기도 합니다(스킬 2단계 검수 5번).
4. **사용자가 듣고 지적한 낱말은 그날 규정집에 올립니다**(`status` "확인"). 같은 부류의 낱말을 그 편에서 함께 고쳤다면 그것도 올립니다(`status` "적용").
5. **낱말로만 올립니다.** 접미사 규칙('-성은 모두 썽')으로 올리지 않습니다. 같은 글자라도 예사소리가 표준인 낱말이 많습니다(아래 표의 오른쪽 칸).
6. **표준 발음은 표준국어대사전의 발음 표기를 따릅니다.** 확인하지 못한 낱말은 올리지 않고, 그 편의 `brief.md` 에 "발음 확인 못 함"으로 적습니다.
7. **장면 코드의 낱말 시각 참조는 `tts` 표기로 씁니다.** `{"sentence": "s08", "word": "사껀"}`, `word('s03', '일반상대썽')`. 타임라인의 글자 시각(`chars`)은 `tts` 의 글자입니다. 맞춤법 표기로 찾으면 "없음" 오류가 납니다(73번에서 겪음).
8. **숫자·단위·로마자의 읽기**는 이 규정집이 아니라 `pipeline/narration/pronounce.py`(자동 변환과 `lint_tts`)와 [NARRATION_AND_CAPTIONS](NARRATION_AND_CAPTIONS.md)가 맡습니다. 소수점 "점"은 된소리로 적지 않습니다(원 저장소 TTS-AP-061 그대로).

### 찾아야 할 부류

| 부류 | 된소리로 적을 것(예) | 같은 글자지만 예사소리가 표준인 것(적지 않음) |
|---|---|---|
| 한자어 접미사 **-성(性)** | 상대성[상대썽], 가능성[가능썽], 안정성[안정썽], 방향성[방향썽], 대칭성[대칭썽], 다양성[다양썽], 방사성[방사썽], 휘발성[휘발썽], 염기성[염기썽] | 관성(慣性), 탄성, 중성, 산성, 자성. 별 이름의 성(星): 위성, 행성, 항성, 혜성 |
| 한자어 **ㄹ 받침 뒤의 ㄷ·ㅅ·ㅈ**(표준발음법 제26항) | 물질[물찔], 발전[발쩐], 발생[발쌩], 결정[결쩡], 밀도[밀또], 절대[절때], 굴절[굴쩔], 질소[질쏘], 발사[발싸] | 결과, 출발, 물체(ㄱ·ㅂ·ㅊ 앞은 해당 없음) |
| **사잇소리**(합성어인데 사이시옷을 적지 않는 것) | 물결[물껼], 눈금[눈끔], 눈동자[눈똥자], 손가락[손까락], 물고기[물꼬기], 계산값[계산깝] | 고기압·물방울처럼 소리가 바뀌지 않는 것 |
| 한자어 **사건·조건·인기·성과·효과** 같은 낱말 | 사건[사껀], 조건[조껀], 인기[인끼], 성과[성꽈] | 효과[효과]와 [효꽈]는 둘 다 허용 — 적지 않음 |
| 관형사형 **-ㄹ 뒤**의 ㄱ·ㄷ·ㅂ·ㅅ·ㅈ | 넣을 수[쑤], 갈수록[갈쑤록], 할 것을[할 꺼슬] | — |

- 엔진이 이 가운데 무엇을 글자대로 읽는지는 다 확인하지 못했습니다. 확인한 것은 '상대성' 하나입니다(사용자 청취). 같은 씨앗으로 두 표기를 합성해 소리를 견준 기계 비교에서는 '눈금'이 뚜렷이 달랐고, '가능성'·'-ㄹ 수'·'-ㄹ수록'은 거의 같았습니다(엔진이 이미 된소리로 읽는 것으로 보임). 이 비교는 청취가 아니며 경계가 흐립니다.
- 그래서 원칙은 **의심스러우면 표준 발음대로 적는다**입니다. 엔진이 이미 맞게 읽는 낱말을 된소리로 적어도 같은 소리가 납니다.
- 받침 뒤의 된소리(물리학자, 조각보, 공식도, 빛줄기, 꼭짓점)는 엔진이 읽습니다. 적지 않습니다.

### 규정집에 올리는 법

`config/pronunciation.json` 의 `words` 에 한 줄을 더합니다.

```json
{"write": "상대성", "say": "상대썽", "status": "확인", "added": "2026-11-28", "why": "…"}
```

- `write` 와 `say` 는 글자 수가 같고 한글뿐이어야 합니다(다르면 `narrate.py` 가 합성 전에 멈춥니다).
- 다른 낱말 안에 들어가도 같은 발음인 것만 올립니다('상대성'은 '일반상대성이론'에서도 [상대썽]).
- 올린 뒤 `python -m pytest -q pipeline/narration/tests/test_pronounce.py`.
- 이미 만든 편의 음성은 바뀌지 않습니다. 그 편을 다시 합성할 때 적용됩니다.

### 올리기 전에 들려 드리기 (2026-11-28 부터, 제작 세션의 제안)

제작 세션은 소리를 듣지 못합니다. 사용자가 그 자리에 있는 제작(밤 자동 제작이 아닌 것)에서는 **음성을 합성한 직후, 화면을 만들기 전에** 내레이션만 보내 드립니다(`outputs/<slug>/narration/narration.wav` 를 mp3 로). 틀린 발음을 이때 잡으면 화면을 다시 렌더하지 않아도 됩니다(73번은 올린 뒤에 발견해 음성 → 화면 → 업로드를 다시 했습니다).
밤 자동 제작에는 들을 사람이 없으므로 규정집과 대본 검수가 유일한 장치입니다. 그래서 사용자가 지적한 낱말은 빠짐없이 규정집에 올립니다.
