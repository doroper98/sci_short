# 과학을 설명하는 소리

2026-10-20 사용자 확정 방향: 영상과 소리가 동떨어지지 않아야 하며, 청각도 과학 설명에 적극적으로 사용한다.
소리는 장면 기획 단계부터 설계한다. 모든 장면에 효과음을 넣거나 모든 물리량을 소리로 바꾸라는 고정 규칙은 아니다.

## 설계 기준

1. **설명할 인과를 먼저 정한다.** 어떤 현상의 변화가 어떤 청각적 차이를 만들며, 그 차이로 무엇을 이해하게 할지 정한다.
2. **화면과 소리는 같은 사건·모형·시간표를 사용한다.** 충돌, 방출, 도착, 진동, 충전·방전 전환을 각각 따로 손으로 맞추지 않는다. 물리적 발생 시각과 관측자에게 도착하는 시각을 구분한다.
3. **과학적으로 필요한 지연도 동기화의 일부다.** 번개와 천둥을 무조건 동시에 재생하지 않는다. 같은 모형에서 파면이 관측자에게 닿을 때 대응하는 소리가 들리게 한다.
4. **소리의 종류를 구분한다.** 실제 현상의 소리, 물리 모형으로 합성한 소리, 데이터를 알아듣게 만든 설명용 소리, 배경음악은 역할과 근거가 다르다. 소리를 내지 않는 현상에 부여한 음향은 실제 소리처럼 소개하지 않는다.
5. **선택한 대응 관계는 비교 구간에서 일관되게 유지한다.** 반복 빈도는 리듬, 진동수는 음높이 등 설명에 필요한 차이를 들려준다. 음량·음높이·음색을 동시에 바꿔 원인을 흐리지 않는다. 음량은 물리량에 무조건 선형 대응시키지 않는다.
6. **중요한 소리를 들을 자리를 만든다.** 핵심 비교에서는 음악과 내레이션을 낮추거나 잠시 비운다. 무음, 도착 전의 기다림, 짧은 반복 비교도 설명에 사용한다. 모든 발전원·입자·장치를 계속 울려 청각적 혼잡을 만들지 않는다.
7. **시간 압축과 슬로모션을 별도로 설계한다.** 과학 시간과 영상 시간을 연결하고 소리를 어떻게 변환했는지 정한다. 시간을 압축했다는 이유로 실제 소리의 음높이까지 무조건 올리지 않는다.

## 주제별 적용 예

| 주제 | 화면과 연결할 청각적 차이 | 피할 오해 |
|---|---|---|
| 천둥 | 번개 경로 각 부분의 거리로 도착 시각을 구하고, 도착음이 겹치며 이어지는 과정을 들려준다 | 번쩍이는 순간 모든 천둥을 재생하거나, 길게 이어지는 이유를 모두 메아리로 설명 |
| 도플러 효과 | 동일한 음원의 관측 주파수 변화를 화면의 이동·파면 간격과 같은 모형으로 생성 | 멀어질 때 단순히 음량만 줄여 음높이 변화를 설명했다고 주장 |
| 진동·공명 | 진동수와 진폭의 변화를 음높이와 크기 변화로 구분해서 비교 | 진폭 증가와 주파수 증가를 혼동 |
| 전력 생산·저장 | 선택한 발전량을 설명용 소리의 밀도·크기로 나타내고, 충전과 방전의 방향 전환을 구별되는 짧은 음형과 연결 | 발전량 증가를 계통 주파수의 상승으로 표현. 전력은 통상 60Hz 계통이며 출력 변화와 같은 변수가 아님 |

전력 영상에서는 발전기 소리·물 흐름 같은 현장음도 실제 장치의 동작에 맞는 경우에만 사용한다.
가상 발전량·SOC를 음향으로 나타내면 영상과 같은 가상 자료를 사용하며, 실제 측정·녹음으로 소개하지 않는다.
모노 휴대전화에서도 핵심 차이가 남도록 설계한다. 좌우 이동만으로 중요한 개념을 전달하지 않는다.
