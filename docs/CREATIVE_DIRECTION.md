# 다양한 과학 주제를 위한 화면 설계

## 결정의 상태

사용자 확정 사항은 **다양한 주제를 다루며 화면을 과도하게 규칙화하지 않는 방향**입니다.
아래는 이를 구현하기 위한 제안이며 특정 도구·장면 수·팔레트·초 단위 템플릿을 승인받았다는 뜻이 아닙니다.

## 고정할 것은 품질, 선택할 것은 표현

| 공통으로 지킬 품질 | 주제마다 선택할 표현 |
|---|---|
| 과학적 인과와 관측/비유 구분 | 입자, 파동, 단면, 실험, 그래프, 캐릭터, 실사, 2D/3D |
| 아이가 지금 무엇을 보고 있는지 이해 | 확대·축소, 분할 화면, 단일 무대, 카메라 시점 |
| 표준 한국어 목소리와 자연스러운 발음 | 설명 문장, 질문 방식, 쉼과 관찰 시간 |
| 읽히고 음성과 맞는 한국어 자막 | 위치·줄바꿈·강조·화면 라벨과의 배치 |
| 약 60~90초 안에서 핵심 질문에 답하기 | 장면 개수, 전환 방식, 장면별 길이, 시작·끝 구성 |

예를 들어 '모든 영상은 픽셀아트', '정확히 다섯 장면', '7초마다 화면 변경', '하단 30%는 항상 자막',
'모든 장면에 수식 또는 캐릭터' 같은 규칙은 다양한 주제를 설명하는 데 불필요한 제약이 됩니다.
한 영상 안에서 대상의 색·모양·의미는 일관되게 유지하되, 다른 주제에서도 같은 색 체계를 강제할 이유는 없습니다.

## 주제에서 화면으로 가는 순서

1. **설명할 질문:** 시청자가 무엇을 궁금해하고 끝에서 무엇을 이해하면 되는지 한 문장으로 씁니다.
2. **원인과 결과:** 무엇을 바꾸면 무엇이 달라지는지 적습니다. 보여줄 수 없는 부분은 명확히 합니다.
3. **보기 어려운 이유:** 너무 작음/빠름/느림/큼/눈에 안 보임/조건 비교가 필요함 중 무엇인지 찾습니다.
4. **표현 선택:** 확대, 슬로모션, 시간 압축, 파동선, 단면, 나란히 비교 등을 목적에 맞게 고릅니다.
5. **비유의 경계:** 그림이 실제 현상과 다른 부분, 오해할 만한 부분을 메모합니다.
6. **짧은 실물 확인:** 대본만 읽지 말고 핵심 움직임과 음성·자막이 함께 있는 구간을 확인합니다.

이 순서는 사고를 돕는 메모입니다. 여섯 종류의 영상 장면이나 상태 머신으로 구현하라는 뜻이 아닙니다.

## 참고자료에서 찾은 표현 도구

| 설명하려는 것 | 선택할 수 있는 기법 | 참고 |
|---|---|---|
| 작은 변화가 큰 결과를 만듦 | 전체 → 확대 → 원인 작동 → 전체 결과 | 망막(1), 전자레인지(6) |
| 보이지 않는 파동 | 파면 간격, 도착 타이밍, 관측자 표시 | 도플러(2) |
| 조건 변화가 관측을 바꿈 | 모형과 관측창 연결, 전후 비교 | 하늘·노을(3) |
| 반복되는 과정과 규모 증가 | 첫 두세 단계를 천천히, 이후 전체로 확대 | 입자 소나기(4) |
| 운동과 신호의 관계 | 물체 운동과 파형을 같은 시간축으로 연결 | 블랙홀(5) |
| 매우 큰 규모의 개념 | 익숙한 물체의 비유, 확대 비율 변경 | 우주 평탄성(7) |

이 목록 밖의 표현도 사용할 수 있어야 합니다. 생물학 구조·화학 반응·기상·지질·천문을 같은 장면 프리셋으로 제한하지 않습니다.

## 제작 코드에 대한 제안

- **내용, 연출, 렌더링을 느슨하게 구분:** 과학 근거·대본을 바꿀 때 엔진 전체를 바꿀 필요가 없고, 연출도 자유롭게 작성할 수 있어야 합니다.
- **얇은 공통 기능:** 음성·자막·시간축·출력·한글 폰트처럼 반복되는 기능을 공유합니다.
- **장면은 자유롭게:** 에피소드별 코드나 자산으로 새로운 표현을 추가할 수 있게 합니다. 고정된 scene_type 목록만 허용하는 구조를 먼저 만들지 않습니다.
- **의미 있는 움직임은 제어 가능하게:** 파동 간격, 궤도, 입자 수, 색 변화 등 설명에 직접 쓰는 움직임은 조건과 결과를 재현·수정할 수 있어야 합니다.
- **생성 자산도 선택지:** 배경·캐릭터 등은 필요에 따라 생성 이미지/영상이나 실사를 사용할 수 있습니다. 과학적 변화가 핵심인 부분은 결과의 일관성을 직접 확인합니다.
- **실제 음성 길이에서 시간축 계산:** 초안 장면 시간을 고정한 뒤 음성을 억지로 압축하지 않습니다.
- **반복을 본 뒤 추출:** 서로 다른 주제에서 유용성이 확인된 파동·입자·확대 요소를 라이브러리로 옮깁니다.

기술 후보로는 Python 기반 시각화/Manim, 웹 Canvas·SVG/Remotion, 필요한 장면의 Blender 등이 있습니다.
이는 검토 목록이며 기술 선택은 아직 하지 않았습니다. 전체를 한 렌더러로 만들지, 장면별 출력을 합칠지도 시제품을 보고 정할 수 있습니다.

## 75초 구성 예시

질문 0~7초 → 관찰·비교 7~20초 → 원인 설명 20~45초 → 조건 변화/재확인 45~62초 → 답 62~75초.

이 시간표는 참고용입니다. 관찰형 실험, 시간 순서형 과정, 규모 비교형 설명마다 다른 구성이 더 나을 수 있습니다.
핵심을 이해하는 데 도움이 되는 정지·반복·침묵은 허용합니다. 움직임의 빈도만으로 영상 품질을 평가하지 않습니다.

## 검토할 때 묻는 질문

- 처음 보는 아이가 무엇이 움직이고 무엇이 달라졌는지 말할 수 있는가?
- 내레이션이 가리키는 대상이 그 순간 화면에 보이는가?
- 확대 장면이 어디인지, 모형과 실제 관측이 어떻게 연결되는지 알 수 있는가?
- 자막을 읽는 동안 중요한 움직임을 놓치지는 않는가?
- 단순화가 새로운 잘못된 인과를 만들지는 않았는가?

이 질문들은 렌더 결과를 검토하는 기준이며, 새 승인 절차나 숫자별 점수제를 만들기 위한 목록은 아닙니다.
